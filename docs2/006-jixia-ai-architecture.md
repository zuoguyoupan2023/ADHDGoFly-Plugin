# 稷下 AI 功能重构规划

## 变更背景

2026-07，网页内悬浮 AI 工作台由 `ExamRoom` 更名为“稷下”（Jixia）。稷下不再被理解为一个聊天窗口，而是当前网页的 AI 阅读与学习工作台。

Side Panel 仍然是插件主体，负责导航、词典、统计、颜色和设置；稷下只在网页内悬浮层中承载 AI 阅读任务。旧的 `agf-*` DOM ID 和内部兼容名称暂时保留，避免破坏已有消息与样式逻辑。

## 实施状态（2026-07）

本规划的 P0、P1、P2 已完成，P3 已完成框架级任务入口的第一阶段：

- 已落地 `JixiaContext`、`JixiaTask`、`JixiaState` 的统一边界。
- Chat、测试和文章任务已经共用上下文、请求、截取、状态和错误处理能力。
- 已落地全文/选区/段落/手动输入上下文切换、测试历史、题目质量校验、自动重试、长文预算控制。
- 统计页已经可以把当前文章导入稷下复习；文章词典已经支持数量选择和本文/基础词典叠加模式。
- Chat 内部的总结、解释、关键词等快捷动作已经移动到稷下框架任务栏。
- 框架任务栏新增“翻译”和“选区解释”；当前两者先复用 Chat 作为结果面板，后续再拆成独立模块。

本阶段的设计结论是：稷下需要像一个“学习工作台”的入口，但不立即做一个与 Side Panel 平行的营销式首页。打开稷下后保留上次使用模块，同时让框架任务栏持续可见；这样既保留熟悉的 Chat 工作流，也让 Chat、测试、翻译、总结等功能成为并列任务入口。

## 与 008 路线的关系

006 是“稷下架构收口”，008 是“基于架构扩展功能”。两份文档中的 P0-P3 不是同一套编号：

- 006 的 P0-P2 指框架、入口、测试和统计/词典联动，当前已完成。
- 006 的 P3 指任务入口和模块化的第一阶段，当前已完成框架任务栏，独立结果视图仍待完成。
- 008 的 P0-P3 指下一轮功能建设，重点是多模态上下文、无障碍、学习闭环、可视化和研究型 Agent。

因此实施顺序是：先完成 006 的架构收尾和验收，再按 008 的 P0、P1、P2、P3 逐级推进。008 的 P0 不要求重做已经完成的文本 `JixiaContext`、`JixiaTask` 和 `JixiaState`，而是在其接口上增加图片、音频、图表和可追溯结果。

## 稷下框架层

框架层不负责具体的聊天气泡或题目卡片，而负责所有模块都需要的共享能力：

- 当前页面标题、URL、正文、选中文本和段落定位。
- 上下文来源：默认全文，也可以切换为选中文本、当前段落或用户手动输入。
- 引用对象：文本、来源位置、页面 URL、内容哈希和截取时间。
- 当前 AI 供应商、模型、Key 状态、请求取消、超时、重试和备用供应商。
- 当前工作模式：`chat`、`quiz`、未来的 `flashcard`、`translate` 等。
- 稷下的常驻、网页高亮、全/中/小尺寸、颜色和显示设置。
- 当前任务状态：空闲、准备上下文、请求中、可交互、失败、已完成。
- 历史记录入口和当前页面会话恢复。

任何模块都通过框架层取得上下文和发起 AI 请求，不再由 Chat 自己独占“读取全文”“读取选区”“切换高亮”这些能力。

## 功能区与 Chat 的拆分

### 功能区

功能区是稷下的控制中心，建议位于顶部或紧凑的工具栏：

- 上下文按钮：全文、选中、当前段落。
- 任务入口：Chat、测试以及未来功能。
- 常驻、高亮、全/中/小窗口切换。
- 当前模型、连接状态和设置入口。

这些控制不属于 Chat，也不应随着 Chat 模式切换而消失。测试模式、翻译模式和未来功能都能调用同一个上下文选择器和高亮状态。

### Chat 模块

Chat 只负责：

- 消息列表和对话历史。
- 用户输入和发送。
- AI 流式输出、复制、重试和继续追问。
- 从当前引用对象生成问题上下文。
- 将总结、解释、关键词等快捷动作转化为 Chat 任务。

Chat 不再直接决定全文或选区的获取方式；它向框架层请求 `contextSource`，再将引用对象交给请求层。

### 测试模块

测试只负责：

- 生成题目。
- 选项作答、判定和解析。
- 原文依据与逐项选项原因。
- 测试历史、未完成测试和难度调整。

测试可以调用 Chat 的部分能力，例如“解释这道题”“为什么这个选项错了”，但不会把测试题目混入普通聊天消息。

## 进入逻辑

稷下打开后是一个框架，而不是直接进入某个固定功能：

```text
打开网页 AI 入口
        ↓
      稷下
        ├─ 功能区：上下文 / 高亮 / 常驻 / 尺寸 / 设置
        ├─ Chat：对话
        ├─ 测试：文章理解
        └─ 未来功能：按需增加模块
```

- 默认进入上次使用的模块，首次进入默认 Chat。
- 点击测试时，默认使用全文；如果用户之前选中了文本，显示“使用选中文本测试”选项。
- 从网页选中文本后打开稷下，功能区显示当前选区，并允许“带选区进入 Chat”或“基于选区测试”。
- 从统计页或词典页进入稷下时，可以携带词汇列表作为引用上下文。
- 功能切换不关闭稷下、不清空上下文，只切换模块视图。
- Chat 与测试共享当前网页上下文，但分别保存会话和测试状态。

## Chat 的引用上下文

建议把上下文表示为统一对象：

```json
{
  "source": "selection",
  "text": "用户选中的文本",
  "pageTitle": "文章标题",
  "pageUrl": "https://example.com/article",
  "paragraph": 4,
  "contentHash": "...",
  "createdAt": 0
}
```

支持的来源：

- `full_article`：当前页面正文，默认测试来源。
- `selection`：用户选中的文本，默认 Chat 引用来源。
- `paragraph`：用户点击或当前阅读位置对应的段落。
- `dictionary`：当前文章词典或选中的词条集合。
- `manual`：用户粘贴或输入的内容。

每个 AI 任务声明自己接受的来源和最大长度，由框架层统一截取、标注和校验。

## 其他可与 Chat、测试并列的功能

建议按学习任务增加，而不是按“AI 能做什么”无限堆按钮：

### 词汇复习

基于文章词典生成词义选择、例句填空、词性判断和间隔复习卡片。

### 选区解释

选中一段文字后给出简释、翻译、改写、例句和上下文含义。

### 结构阅读

提取文章主旨、论点、证据、因果关系、争议点和章节结构。

### 写作辅助

基于文章或选区生成摘要、笔记、提纲、引用卡片和读后感草稿。

### 事实与观点辨识

区分文章中的事实、推论、观点和需要验证的说法，并保留原文依据。

### 翻译与语言学习

按段落翻译、难句拆解、词性标注、例句生成和双语对照。

首批建议只实现“选区解释”和“词汇复习”，因为它们可以直接复用当前上下文、词典和高亮能力。

## 验收标准

- 稷下打开后能够清晰看到当前模块和功能区。
- Chat、测试都可以选择全文、选区或段落作为上下文。
- 常驻、高亮、窗口尺寸和设置在切换模块后仍然有效。
- 测试不会把题目、选项和答案混入 Chat 历史。
- Chat 可以引用选区或测试题目继续追问。
- 新增功能不需要复制一套页面抓取、供应商配置或错误处理逻辑。
